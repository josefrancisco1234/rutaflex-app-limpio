RutaFlex · Backend PHP 8.1+ y PostgreSQL

Requisitos: PHP 8.1+ con la extensión pdo_pgsql, y PostgreSQL 12+.

1) Base de datos
   createdb rutaflex
   psql -d rutaflex -f backend/schema.sql

2) Usuario de base de datos con permisos mínimos (recomendado)
   psql -d rutaflex -v app_pass='una-clave-segura' -f backend/roles.sql
   y en backend/.env:  DB_USER=rutaflex_app  DB_PASS=una-clave-segura
   (la app solo lee y escribe filas; no puede borrar tablas ni crear usuarios).

   Configuración: copiar backend/.env.example a backend/.env y poner los datos de conexión.

3) Servidor de desarrollo (puerto 8000)
   php -S localhost:8000 -t backend/public backend/public/index.php

4) Frontend (Vite reenvía /api al puerto 8000)
   cd frontend
   copiar .env.example a .env
   npm install
   npm run dev

Seguridad (sesiones)
   /api/login devuelve {id, token}. Las demás llamadas envían el header
       Authorization: Bearer <token>
   y el servidor identifica al usuario con el token (tabla sesiones; solo se guarda su hash SHA-256),
   nunca con un id que venga en el cuerpo. Si el cuerpo trae user/driver/admin distinto al de la
   sesión, responde 403. Sin sesión o con token vencido responde 401.
   La sesión dura SESSION_HOURS (12 h por defecto); logout y suspensión la invalidan al instante.

API: todos los endpoints son POST con cuerpo JSON.
   POST /api/data     {hash?}      -> datos visibles para quien pregunta, o {"unchanged":true}
        Sin sesión: viajes y perfiles públicos. Con sesión: además sus chats y avisos.
        Correo, celular, licencia, código universitario y motivos solo los ven el dueño y los admins.
        La ubicación en vivo de un viaje solo la ven sus participantes.
   POST /api/sync     {p:{users,trips,messages,ratings,notices}}   (requiere sesión)
        Cada registro se acepta solo si le pertenece al usuario de la sesión: su perfil (nombre y
        preferencias), sus viajes como conductor, su asiento como pasajero, sus mensajes, sus
        calificaciones y los avisos a participantes de sus viajes. No cambia contraseñas, correo,
        rol, verificación, reputación ni viajes completados (esos los calcula el servidor).
   POST /api/login    {email,pass} -> {id, token} o null
   POST /api/register {p:{name,email,pass,role,phone?,application?}} -> true          US02
        Valida el dominio institucional en el servidor; contraseña de 8 a 72 caracteres.
   POST /api/reset    {p:{...}}    -> reinicia la demo con los datos enviados (solo DEMO_MODE=true)

   Release 2 (requieren sesión; validan las reglas en el servidor; errores con {"error": "..."} y código 4xx):
   POST /api/logout         {user}                  -> true                        US03
   POST /api/profile        {user, p:{name, phone?, career?, bio?, zone?, prefTime?, car?}}  US04
   POST /api/verify         {user, code}            -> true (código de 8 dígitos)  US20
   POST /api/edit-trip      {trip, driver, p:{origin?, dest?, time?, seats?, price?, changes?}}  US11
   POST /api/cancel-trip    {trip, driver, reason}  -> true                        US12
   POST /api/notifications  {user}                  -> últimos 100 avisos          US15 · US16
   POST /api/mark-read      {user}                  -> cantidad marcada            US15 · US16
   POST /api/co2            {user}                  -> kg de CO2 evitados          US23

   Administración (el usuario de la sesión debe ser un administrador activo):
   POST /api/driver-apply   {user, p:{model, plate, license, soat, phone}}  -> true   (reenviar solicitud rechazada)
   POST /api/admin-review   {admin, user, approve, reason?}  -> true   (rechazar exige motivo; se notifica)
   POST /api/admin-ban      {admin, user, ban, reason?}      -> true   (suspender exige motivo)
   POST /api/admin-delete   {admin, user}                    -> true

   Los conductores que se registran quedan "pendiente" hasta que un admin los aprueba;
   mientras tanto no pueden publicar viajes. /api/sync no permite crear admins ni cambiar
   rol, estado de la solicitud o suspensión. Las cuentas suspendidas no pueden iniciar sesión.

Crear un administrador (nadie puede registrarse como admin desde la app):
   php backend/bin/crear-admin.php admin@aloe.ulima.edu.pe "Nombre" "contraseña"

Actualizar una base del Release 1: basta con volver a ejecutar
   psql -d rutaflex -f backend/schema.sql
(agrega las columnas verificado/extra, el estado Cancelado y la tabla notificaciones sin borrar datos).

En producción con Apache se usa backend/public como raíz (el .htaccess redirige a index.php)
y el frontend (npm run build) se sirve desde el mismo dominio bajo la ruta que corresponda.
